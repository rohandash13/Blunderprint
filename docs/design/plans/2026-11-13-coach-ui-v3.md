## Global Constraints

- Steps: Landing → Analyzing → Profile (1) → Choose focus (2) → Drill (3). Pattern names/descriptions come from the existing `patternLabels.ts` (with `positional`).
- Coach-paced lines: `next_move` animates exactly one ply; captions are deterministic from facts; the LLM never gets FEN/UCI/Elo/percentages.
- Public analysis limits: 40 games, reuse DONE runs < 7 days, global 40 runs/day, 3 per IP/day, queue FIFO.
- Visual: Club Wallchart palette #1F4D3A rail, cool-white paper (not cream), ink #1A1A1A, marker red #D7263D, highlighter #F2D94E, board #F0D9B5/#B58863; tabular figures; standard controls; no kicker labels above headings; read `.claude/skills/impeccable/reference/craft-floor.md` before any UI edit.

### Task U1: Profile and position endpoints (backend)
Files: new `report/ProfileService.java`, `lichess/LichessClient.java` (add `fetchUser(username)` → perfs map, 10-min cache, null on failure), `api/AnalysisController.java` (or a new `ProfileController`), tests.
Produces exactly the JSON in spec §2: `GET /players/{u}/profile` and `GET /players/{u}/positions/{gameId}/{ply}` (Example shape from ReportService, reuse its row mapping). Player colour = game.white/black matched case-insensitively. Phase rule: opening ply ≤ 20, endgame ≤ 4 non-pawn non-king pieces from `before_fen`, else middlegame. Candidate rule = `Severity.CANDIDATE_SQL`; primary pattern = ReportService's priority logic (extract to a shared static if needed).
Tests: ITs seeding games/moves/analysis for colour/record, phases, grid ordering and marks, patterns aggregate, Lichess down → ratings null (mock client), 404 when no run; position endpoint returns Example / 404.

### Task U2: Public analysis gate (backend)
Files: new `analysis/AnalysisGate.java` (+ clock injection), `api/AnalysisController.java`, `config/DemoModeFilter.java` (stop blocking `POST /analysis`; keep `/admin/**` and `/analysis/*/reenqueue` blocked), `application.yml` (`analysis.max-runs-per-day: 40`, `analysis.max-runs-per-ip-per-day: 3`, `analysis.max-games: 40`, `analysis.reuse-days: 7`), progress response gains `queuePosition`; new `GET /players/{u}/status`.
Behaviour per spec §4 (client IP: last X-Forwarded-For hop, as VoiceRateLimitFilter does — share the helper). Unknown user / no rated games → 404 with message (check what IngestService does with an empty fetch and map it).
Tests: reuse within 7 days, queue position for a second run, caps → 429 with injected clock and IPs, DEMO_MODE off keeps old behaviour, status endpoint.
